Block 00 · the definition

What a language model is

A language model is a probability distribution over strings. That is the whole definition — nothing about neural networks, nothing about generation. Given a sequence of tokens w1…wT, it assigns a number P(w1,…,wT), and the numbers over all possible sequences sum to one.

Nobody can estimate P(w1,…,wT) directly: the number of possible 30-token sentences over an 8 000-token vocabulary is 800030. So the first move — Shannon's, in 1948 — is the chain rule: P(w1,…,wT)=∏tP(wt|w1,…,wt-1), the probability of a text as a product of the probabilities of each next token given everything before it.

Block 01 · the task

The task at one position

Every position is a classification problem with |V|=8,000 classes: given the state, predict the next piece. The input at step t is the token wt; the target is wt+1. So the model's input sequence is the joke with [BOS] in front, the target sequence is the same joke shifted left by one with [EOS] at the end.

One forward pass over a text therefore trains every position at once. Two tokens are added around the text: [BOS] in front, so that the first real token also has something to be predicted from, and [EOS] at the end, so that the model learns when a text stops — without it, it could never stop generating. Texts have different lengths and a tensor does not, so a batch is padded with [PAD] to its longest text.

Block 02 · the metric

A number for the model, and the number that lies

Looking at samples is not a metric. The metric for a language model is how much probability it assigns to text it has not seen, and by convention we report it as perplexity: PPL=exp(-1T∑tlogP(wt|w<t)). Lower is better.

A count model estimates every probability as a ratio of counts. That leaves the question of what it does with a continuation it has never counted — and on held-out text such continuations are not rare, because the number of possible n-grams grows exponentially with n while a corpus grows linearly. The problem is called sparsity.

Perplexity is an average per token, so it depends on what a token is. The same text cut into words and cut into subword pieces has a different number of tokens and a different difficulty per token. To compare models with different tokenizers, the same negative log-likelihood is divided by the number of characters instead — bits per character — because characters do not depend on the tokenizer.

Block 03 · counting

Counting, and its ceiling

The chain rule needs P(wt|w1,…,wt-1), a distribution conditioned on the entire prefix. Nobody has counts for entire prefixes. So the second move is an approximation, the Markov assumption: only the last n−1 tokens matter. This is a lie, and a useful one — with n=3 the model needs counts of triples, and triples we have.

The fix for sparsity is to stop trusting raw counts. Add-δ (Laplace) smoothing pretends that every possible continuation was seen δ extra times. Interpolation mixes the trigram estimate with the bigram and the unigram, so that when the long context was never seen, the short one still speaks. Kneser–Ney also changes what the lower-order model counts, and was the state of the art for twenty years.

Block 04 · learning

Learning instead of counting

Counting has a ceiling and we just hit it. The reason is not the amount of data; it is that a count-based model treats every prefix as an unrelated symbol. Штирлиц открыл and Мюллер открыл share nothing — even though whatever follows one probably follows the other. The recurrent network drops the window: instead of looking at the last n−1 tokens, it maintains a state vector ht that is updated once per token and is supposed to summarise everything so far: ht=f(ht-1,xt), P(wt+1|w≤t)=softmax(Wht).

Why should a network do better than counting? Because of embeddings. Bengio et al. (2003) built the first neural language model by concatenating the embeddings of the last n−1 words and putting a network on top — the same Markov assumption, but now cat and dog share statistics through their vectors. The recurrent network keeps that and drops the window.

Everything so far generates text from nothing but a prefix. The moment you want to generate text from an input — translate a sentence, summarise a document, answer a question — you need one more idea: condition the language model on a second sequence. The encoder–decoder (Sutskever et al. 2014; Cho et al. 2014) does it in the most direct way: one network reads the input into a vector, a second one generates from it.

Training a decoder has one choice the architecture does not make for you: what it reads as its previous token during training — the reference translation, or its own guess.

Block 05 · the right factor

The decoding rule

We have a model that, given a prefix, returns a distribution over 8 000 next tokens. Everything below operates on a single vector of logits for one position; each rule is a small function that turns that vector into a chosen token id. Whatever the model, the interface is the same, which is why the code that generates from a 6M-parameter LSTM is byte-for-byte the code that drives a 400B-parameter LLM.

The rules come in a few kinds. Greedy takes the most probable token every time; sampling draws from the distribution as the model gives it. Temperature divides the logits by T before the softmax: T<1 sharpens the distribution, T>1 flattens it, T→0 is greedy. Truncation cuts the tail off before sampling: top-k keeps the k most probable tokens, top-p (nucleus) the smallest set whose probabilities sum to p, min-p every token at least pmin times as probable as the top one. A repetition penalty lowers the logits of tokens already used. Beam search is different in kind: it keeps the b most probable sequences and extends all of them.

The tail of the distribution — thousands of tokens with tiny probability each — is where incoherence comes from, and truncation cuts it off. The rules differ in how they decide where the tail starts.

Why is the most probable text not the best text? Holtzman et al. (2020) answered with one picture: take a real text and, at every position, ask the model what probability it gave to the token that actually came next; then do the same for the model's own greedy continuation, and compare the two curves.
