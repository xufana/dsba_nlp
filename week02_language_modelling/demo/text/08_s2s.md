# s2s · Encoder–decoder: a language model that starts from a summary

## s2s-p1

Everything so far generates from nothing but a prefix. The moment you want to generate text *from an input* — translate, summarise, answer — you need one more idea: condition the language model on a second sequence. The encoder–decoder does it in the most direct way imaginable. One RNN reads the input and boils it down to a fixed-size vector. A second RNN is a language model exactly like block 04, except its initial state is that vector instead of zeros. Same chain rule, same decoding rules — one extra input. The task is the classic teaching one: German → English on Multi30k, 29 000 image captions.

## s2s-note1

The diagram is the whole model, and it contains its famous flaw. Everything the decoder knows about the German sentence has to pass through the red vector — the encoder's final state, two directions concatenated (512 numbers) and projected down to 256. A three-word caption and a twenty-word caption are compressed to the same 256 numbers. That is the **bottleneck**, and next week's entire topic exists to remove it. Training uses **teacher forcing** — the decoder is fed the gold prefix no matter what it would have predicted — which is what makes training fast and parallel, and which plants **exposure bias**: at generation time the decoder feeds on its own, possibly wrong, output, a situation it never saw in training.

## s2s-note2

**BLEU** is the score: what fraction of the generated n-grams (n = 1..4) appear in the reference, combined geometrically, times a brevity penalty that punishes translations shorter than the reference. It is crude — it does not know synonyms — and it is the metric machine translation ran on for twenty years, because it correlates with human judgement in aggregate. One rule: BLEU implementations disagree, so use *one* throughout. We use <span class="mono">sacrebleu</span>.

## s2s-p2

Everything block 07 said, as one piece of code: pairs into padded batches, the encoder that packs its input so it never reads <span class="mono">[PAD]</span>, the projection that *is* the bottleneck, and one decoder with two entry points — <span class="mono">forward</span> for training, where the gold prefix goes in, and <span class="mono">greedy</span> for inference, where its own output does. Then the loop and the score.

## s2s-note3

The two methods of the decoder are the two diagrams from block 04 again. <span class="mono">forward</span> takes the whole target at once and returns logits for every position, because the inputs are known; <span class="mono">greedy</span> takes one token, returns one distribution, picks, and feeds the pick back — forty sequential calls where training needed one. Same weights, same recurrence; everything block 08 measures about the bottleneck is a property of the two <span class="mono">_proj</span> lines.

## tr-note

The translations get the nouns right — the actors and objects survive — and often get the *action* wrong. A red shirt becomes a blue shirt; the participants make it through the bottleneck, the details do not. That is the fingerprint of the fixed-size summary: it has room for *what the sentence is about* but not for *everything it says*.
