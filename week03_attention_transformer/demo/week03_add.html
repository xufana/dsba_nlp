Машинный перевод и трансформер

Как перейти от генерации перевода к сети, в которой токены обмениваются информацией через attention.

В языковой модели предсказываем продолжение по префиксу. В переводе к этому условию добавляется исходный текст. Длина перевода и порядок слов могут отличаться от исходной последовательности.

блок 01

Как поставить задачу перевода?

Энкодер читает источник, декодер генерирует перевод. В рекуррентном encoder–decoder последнее состояние энкодера инициализирует декодер. Затем каждый шаг декодера использует предыдущее состояние и очередной входной токен.

P(y|x)=∏t=1TP(yt|y<t,x)

x — весь источник, y<t — уже известный префикс перевода. EOS завершает последовательность. При обучении в декодер подаём эталонный префикс, при генерации — выбранные моделью токены. Ошибку считаем по правильным токенам перевода, исключая PAD.

Обе сети развёрнуты по времени: одна ячейка — один шаг. Энкодер читает «the cat sleeps», декодер начинает с BOS и генерирует «кошка спит EOS». Между ними — только последнее состояние энкодера: d чисел. Переключите длину источника: состояний энкодера стало больше, а вектор на границе тот же.

блок 02

Как оценить перевод?

Вероятность перевода — оценка модели. Чтобы проверить качество, нужны отложенные пары предложений с эталонными переводами. Самая известная автоматическая метрика — BLEU. Она сравнивает перевод с эталоном по n-граммам, n от 1 до 4.

Для каждого n считаем точность: какая доля n-грамм перевода встречается в эталоне. Одну n-грамму засчитываем не больше раз, чем она встречается в эталоне:

pn=∑gmin(counthyp(g),countref(g))∑gcounthyp(g)

Точность не наказывает за пропуски: верный короткий кусок эталона получит все pn=1. Поэтому добавляем штраф за краткость, где c — длина перевода, r — длина эталона:

BP=min(1,exp(1−r/c))

BLEU — среднее геометрическое четырёх точностей, умноженное на штраф. Обычно его умножают на 100.

BLEU=BP·exp(14∑n=14ln(pn))

Каждая часть формулы закрывает одну лазейку. Точность учитывает только точные совпадения строк: «кот» и «кошка» для неё разные токены. Ограничение countref не даёт набрать точность повтором одного верного слова. BP не даёт выиграть, выбросив сомнительный хвост. Проверки смысла в формуле нет.

Эталон фиксирован. Выберите вариант или впишите свой перевод, слова через пробел. Зелёная n-грамма есть в эталоне; перечёркнутая есть, но в переводе повторяется чаще, чем в эталоне, и сверх этого не засчитывается. BLEU здесь — по одному предложению и без сглаживания, как в исходной формуле.

На практике BLEU считают по всему тестовому корпусу: числители и знаменатели pn суммируют по всем предложениям, c и r — тоже. Поэтому одно предложение без общих четырёхграмм не обнуляет результат; для оценки отдельного предложения используют сглаживание. Несколько эталонных переводов частично помогают с перефразами: ограничение совпадений берётся по эталону, где n-грамма встречается чаще всего.

Высокий BLEU на корпусе означает, что переводы в среднем близки к эталонам по словам. Он не гарантирует, что сохранён каждый факт.

блок 03

Как читать источник на каждом шаге?

Сохраним состояния энкодера на всех позициях. На каждом шаге декодер сравнивает своё состояние с каждым состоянием источника. Обучаемая функция выдаёт оценки соответствия, softmax превращает их в веса, а взвешенная сумма состояний даёт контекст текущего шага.

et,i=score(st,hi)
αt,i=exp(et,i)∑j=1Sexp(et,j)
ct=∑i=1Sαt,ihi

hi — состояние энкодера, st — текущее состояние декодера, S — длина источника. Выходной слой использует состояние декодера и контекст. При следующем слове состояние декодера меняется, поэтому меняются и веса. Обе сети и функция соответствия обучаются по ошибке перевода.

Та же развёрнутая RNN, что в блоке 01. Без attention декодер видит источник только через последнее состояние энкодера. С attention на каждом шаге все hi смешиваются с весами αt,i в контекст ct; толщина линии — вес. Контекст идёт в выходной слой вместе с st. Выберите шаг: состояние декодера другое, поэтому другие и веса. Оценки учебные, не обученные; это не лингвистическая разметка.

scores = score(decoder_state, encoder_states)scores = scores.masked_fill(source_ids == pad_id, -torch.inf)weights = scores.softmax(dim=-1)context = (weights[..., None] * encoder_states).sum(dim=1)logits = head(torch.cat([decoder_state, context], dim=-1))

Матрицу весов можно рассмотреть: строка соответствует шагу перевода, столбец — позиции источника. Для обучения достаточно пар предложений; соответствия отдельных слов не обязательны. Большой вес показывает вклад позиции в данную взвешенную сумму. Сам по себе он не объясняет весь выбор выходного слова.

блок 04

Self-attention: запросы, ключи и значения

Теперь построим представление каждого токена через другие токены той же последовательности. Это self-attention: для каждой позиции вычисляем свой набор весов и собираем свой контекст. Рекуррентный перенос состояния для этого не требуется. Внутри слоя позиции можно вычислять параллельно.

Как определить, какую информацию собирать и что передавать? Из входных представлений X тремя обучаемыми линейными преобразованиями получаем Q (queries, запросы), K (keys, ключи) и V (values, значения). Запрос позиции сравнивается с ключами доступных позиций. Полученные веса определяют, как смешать значения.

Q=XWQ,K=XWK,V=XWV

Столбцы — токены, строки — шаги расчёта, как в рисунках Alammar (2018). Векторы q, k, v получены из x учебными матрицами (под катом), обучения здесь нет. Запрос выбранной позиции сравнивается с ключами всех трёх позиций; softmax даёт веса; выход z — смесь значений с этими весами. Смените запрос: меняются оценки, веса и z, а k и v остаются прежними.

матрицы учебного примера
X = torch.tensor([[1., 0.], [0., 1.], [1., 1.]])W_Q = torch.eye(2)W_K = torch.tensor([[1., 1.], [0., 1.]])W_V = torch.tensor([[1., 0.], [1., 1.]])Q, K, V = X @ W_Q, X @ W_K, X @ W_VA = (Q @ K.T / math.sqrt(2)).softmax(dim=-1)Z = A @ V

Скалярные произведения всех запросов со всеми ключами образуют матрицу T×S. В self-attention T=S. Делим оценки на dk, применяем маску, затем softmax по ключам в каждой строке. Результат умножаем на V.

A=softmax(QKTdk+M)
Z=AV

dk — ширина запроса и ключа одной головы. При независимых компонентах единичной дисперсии дисперсия скалярного произведения растёт с dk; масштабирование сдерживает этот рост. M равно нулю на разрешённых парах и −∞ на запрещённых. Каждая строка должна содержать разрешённый ключ.

Те же числа в матричной форме. Выделенная строка S, A и Z — расчёт выбранного запроса со схемы выше. В self-attention энкодера без PAD маска нулевая; в блоке 05 она станет нужна.

scores = q @ k.transpose(-2, -1) / math.sqrt(q.size(-1))scores = scores.masked_fill(~allowed, -torch.inf)weights = scores.softmax(dim=-1)output = weights @ v

блок 05

Кто кого читает?

Self-attention энкодера: Q, K и V получаем из представлений источника. Каждая позиция может читать весь источник, кроме PAD.

Causal self-attention декодера: Q, K и V получаем из представлений перевода. Позиция читает себя и предыдущие позиции; будущие закрыты маской. При teacher forcing на входе лежит весь сдвинутый эталон, поэтому без маски модель увидит ответы.

Cross-attention декодера: Q получаем из текущих представлений декодера, K и V — из выходов энкодера. Перевод читает источник; скрывать последующие слова источника не требуется.

Сверху — токены и стрелки от выбранного запроса к позициям, которые он читает, снизу — та же маска матрицей. Нажмите на токен или клетку. В cross-attention запросы и ключи из разных последовательностей: строк три, столбцов четыре, и ключи с значениями одни и те же для каждого шага перевода.

Обучение предсказанию следующего токена можно распараллелить по позициям, потому что эталонный префикс уже известен. При генерации следующий вход становится известен после выбора токена. Поэтому авторегрессионная генерация остаётся последовательной и у трансформера.

блок 06

Несколько голов и порядок токенов

Одна голова даёт одно распределение весов для каждого запроса. В multi-head attention несколько голов строят распределения параллельно, со своими проекциями Q, K и V. Их выходы объединяются по признакам и проходят через выходное линейное преобразование. Конкретные роли голов заранее не задаём.

При ширине модели d и числе голов H ширина одной головы равна d/H. После разделения тензор имеет оси «батч, голова, позиция, признак». После attention возвращаем оси «батч, позиция, признак».

Разделяем признаки, сохраняя все позиции в каждой голове. После смешивания значений объединяем головы и применяем W_O. Простое копирование одной готовой карты attention не создаёт разных обучаемых голов.

Self-attention с полной маской без позиционной информации перестановочно эквивариантен: переставим входные строки — так же переставятся выходные. Для понимания порядка добавляем информацию о позициях. В ноутбуке используем обучаемые позиционные эмбеддинги; в исходном трансформере были синусоидальные. Причинная маска тоже ограничивает порядок доступа, но не заменяет явную информацию о расстояниях между токенами.

блок 07

Из attention собираем блок

В трансформере attention переносит информацию между позициями, а FFN применяет одну и ту же двухслойную сеть к каждой позиции отдельно. Residual складывает вход подслоя с его выходом. LayerNorm нормирует признаки внутри вектора одной позиции; его параметры обучаются.

На схеме и в ноутбуке используем Pre-LN: сначала нормализация, затем подслой, затем прибавление к входу. В исходной статье используется Post-LN. Dropout в учебном блоке опущен; это позволяет напрямую проверять вычисления.

Две позиции, как у Alammar (2018): attention — одна широкая плашка, потому что смешивает позиции; LayerNorm и FFN нарисованы отдельно на каждой позиции, с общими весами. Пунктир — residual: вход подслоя прибавляется к его выходу, ширина d сохраняется. У Alammar и в исходной статье Post-LN, «Add & Normalize» после подслоя; здесь Pre-LN, как в ноутбуке занятия 4.

normalized = norm1(x)x = x + attention(normalized, allowed)normalized = norm2(x)x = x + ffn(normalized)

блок 08

Полный переводчик

Энкодер переводчика получает эмбеддинги источника с позициями и применяет несколько блоков self-attention + FFN. Декодер получает сдвинутый перевод с позициями. Каждый блок декодера содержит causal self-attention, cross-attention к выходу энкодера и FFN. У каждого подслоя есть нормализация и residual. Линейный выходной слой даёт оценки токенов целевого словаря, softmax — их вероятности.

Число блоков энкодера и декодера выбираем при построении модели. Веса разных блоков обычно различаются. При обучении cross-entropy сравнивает предсказания с переводом, сдвинутым на один токен вперёд; PAD исключаем из loss.

Схема по Alammar (2018): два блока энкодера, блок декодера целиком, второй свёрнут. Выход последнего блока энкодера даёт K и V для cross-attention каждого блока декодера; запросы приходят снизу, из самого декодера. Подписи «Add & Norm» — Post-LN исходной статьи. В ноутбуке занятия 4 реализуем причинный блок языковой модели; у него нет источника и cross-attention.
