## decode-intro

**Greedy** берёт самый вероятный токен. **Sampling** выбирает случайно согласно распределению. Температура делит логиты до softmax: при T < 1 распределение острее, при T > 1 — ровнее. Top-k оставляет k кандидатов; top-p — минимальное число кандидатов, суммарная вероятность которых достигает p.

## decode-note

Учебные логиты фиксированы. Меняем температуру и top-p, затем пересчитываем вероятности и оставленное множество. После отсечения снова нормируем. Серые столбики — исходное распределение после температуры, цветные — распределение для выбора.

## decode-detail

Температура меняет отношения вероятностей. Отсечение сохраняет отношения между оставленными кандидатами и убирает остальных. Seed определяет случайный выбор при фиксированных условиях; сам по себе распределение не меняет.

Greedy максимизирует вероятность текущего шага. Это не гарантирует ни самую вероятную последовательность, ни лучший текст. Повторы и бессвязные продолжения возможны при разных правилах: проверяем конкретную модель, префиксы и настройки.

Min-p оставляет токены относительно вероятности самого вероятного. Repetition penalty меняет оценки уже использованных токенов; способ изменения должен учитывать знак логита. Эти настройки можно исследовать в полном семинаре.

## q-decode · sort

Что меняет каждая настройка?

bins: отношения вероятностей · множество кандидатов · случайный выбор
- температура → отношения вероятностей
- top-k → множество кандидатов
- top-p → множество кандидатов
- seed → случайный выбор

> Температура перераспределяет массу, отсечение убирает кандидатов, seed выбирает конкретную случайную траекторию. После отсечения оставленные вероятности нормируем.

## q-quality · write

Модель хорошо предсказывает настоящие продолжения на тесте. Достаточно ли этого для утверждения, что greedy даст хороший текст?

- оценка на настоящих префиксах отличается от генерации на собственных
- greedy выбирает локальный максимум
- нужны отдельные проверки генерации и требований задачи

> При генерации модель получает собственные продолжения. Ошибки меняют последующий контекст, а локально вероятный выбор может быть неудачным для всей последовательности. Проверяем результат генерации отдельно.

## code-decode
```python
probabilities = (logits / temperature).softmax(dim=-1)  # @temperature
values, ids = probabilities.sort(descending=True)
keep = values.cumsum(dim=-1) - values < top_p  # @truncate
filtered = values * keep
filtered = filtered / filtered.sum(dim=-1, keepdim=True)  # @renorm
choice = torch.multinomial(filtered, 1)  # @choice
next_id = ids.gather(-1, choice)
```
