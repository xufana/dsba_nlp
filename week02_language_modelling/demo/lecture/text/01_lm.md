# lm · What a language model is

## lm-p1

A **language model** is a probability distribution over strings. That is the whole definition — nothing about neural networks, nothing about generation. Given a sequence of tokens $w_1 … w_T$, it assigns a number $P(w_1, …, w_T)$, and the numbers over all possible sequences sum to one.

## q-lm-sort · sort

Which of these is a language model, in that sense?

bins: a language model · not a language model

- a bigram counter over 124 000 jokes → a language model
- an LSTM trained to predict the next BPE piece → a language model
- GPT-2 → a language model
- tf-idf and logistic regression over headlines → not a language model
- word2vec → not a language model
- a web search engine → not a language model
- BERT → a language model | not a language model

> Three of them assign a probability to any string by the chain rule: the counter, the LSTM and GPT-2 differ only in how $P(w_t | w_{<t})$ is computed. The classifier models $P(\mathrm{label} | \mathrm{text})$ — the text is on the wrong side of the bar. word2vec models $P(\mathrm{context} | \mathrm{word})$, one pair at a time; it never multiplies anything into a probability of a sentence. Search ranks documents; it has no distribution over strings at all.
>
> BERT is the honest "it depends". It is trained as a *masked* language model — $P(w_i | \text{everything else})$ with both sides visible — and those conditionals do not chain into a joint $P(w_1 … w_T)$. It is a language model by name and by training signal, and not a distribution over strings you can sample from. Both bins are defensible; what is not defensible is "it generates text".
> miss: if word2vec went in: it is trained like a tiny language model with a two-word window, which is exactly why the confusion exists. The difference is that nobody ever asks it for the probability of a sentence.

## lm-p2

Nobody can estimate $P(w_1, …, w_T)$ directly: the number of possible 30-token sentences over an 8 000-token vocabulary is $8000^{30}$. So the first move — Shannon's, in 1948 — is the chain rule: $P(w_1, …, w_T) = ∏_t P(w_t | w_1, …, w_{t-1})$, the probability of a text as a product of the probabilities of each next token given everything before it.

## q-chain · pick

What did the chain rule buy?

- [x] it turns "how likely is this text" into "how likely is the next token, given everything so far" — a question a model can answer one step at a time — and loses nothing
- [ ] it makes the model smaller: only the last few tokens are kept
- [ ] it is an approximation that happens to work well in practice
- [ ] it makes the probabilities of all sentences sum to one

> It is an identity; nothing is lost and nothing is approximated. What changes is the question: from a joint over all strings to one conditional per position — and *that* question a model can answer one step at a time, which is why every language model since is a different way to approximate the right-hand side. Shrinking the context to the last few tokens is the *next* move, the Markov assumption, and that one is a lie — a useful one.
> miss: if "an approximation": you are thinking of the Markov assumption. The chain rule is exact; the n-gram model is what you get after you also truncate the condition.
