# Changelog

Notable changes to the seminar notebooks and their environments, newest first. Each entry gives the date, what changed and why.

## 2026-10-13: autumn 2025 notebooks, pinned environments and fixes

Why: the notebooks were written against `transformers` 4.x, `datasets` 3.x and `langchain` 0.3, and the next major versions of these libraries removed APIs the notebooks call, so "Run all" failed on a fresh install. Several notebooks also had bugs that do not depend on versions. The pins are `transformers>=4.56,<5`, `datasets>=3.6,<4`, `langchain*<1` and `sentence-transformers<5`. Notebooks that are new in this repository arrive in two commits, the notebook as taught (saved outputs included) and then the fixes; the course notes at fpakhurov.com link to the first one, so its cell numbers and outputs match what the notes describe.

- **Environment** ([#1](https://github.com/xufana/dsba_nlp/pull/1)). `pyproject.toml` with one `uv` dependency group per week (`uv sync --group week03`), a `cuda` group for the Linux + NVIDIA-only packages (vLLM, bitsandbytes, GPTQModel) and a `gemini` group; `uv.lock` regenerated; `seminars/README.md` with how to run, why the pins, a per-week table and how to run without W&B, Gemini or Hugging Face accounts. Every notebook starts with a `%pip install` cell that installs the same pinned list, so Colab needs no local setup. Replaces the previous single dependency list, which pinned `torch==2.2.2` and covered weeks 1–2 only.
- **Week 1** ([#2](https://github.com/xufana/dsba_nlp/pull/2)). The `# YOUR CODE` cells have reference solutions (tokenization, word vectors, phrase embedding, nearest neighbours, the final classifier on averaged vectors). The Quora file is downloaded only if it is missing; NLTK corpora are downloaded in the cells that use them.
- **Week 2** ([#3](https://github.com/xufana/dsba_nlp/pull/3)). The device is detected (`cuda`, then `mps`, then `cpu`) instead of a hard-coded `mps`. W&B is optional (`WANDB_MODE=disabled` by default) and the metrics are printed after every epoch. The GRU block prints its result.
- **Week 3** ([#4](https://github.com/xufana/dsba_nlp/pull/4)). `LaplaceLanguageModel` called a method that does not exist; the probability-sum check was vacuous (`sum(list, 1)`); the RNN-LM section used an undefined train/test split and lacked `import math`. Sequences are capped at 128 BPE tokens and the batch at 64 so the `(batch, length, vocab)` logits fit in memory, and a note says the RNN training needs a CUDA GPU. `data/anek.txt` and `pictures/bpe-example.png`, which the notebook reads, are added.
- **Week 4** ([#5](https://github.com/xufana/dsba_nlp/pull/5)). W&B is optional; `evaluate` returns BLEU and the training loops print it. The `weights/` directory the notebook saves checkpoints to is added.
- **Week 5** ([#6](https://github.com/xufana/dsba_nlp/pull/6)). `PAD_ID` was read from `pad_token_type_id` (the segment id) instead of `pad_token_id`; `num_proc=30` is replaced by the number of cores.
- **Week 6** ([#7](https://github.com/xufana/dsba_nlp/pull/7)). `compute_metrics=accuracy.computes` (no such attribute) is replaced by a metric function; the `multi_class` argument removed in scikit-learn 1.7 is dropped; `ag_news` is loaded under its current Hub id. Bonus NER notebook: `conll2003` loaded as `eriktks/conll2003` with `trust_remote_code`, `evaluation_strategy` → `eval_strategy` (removed in transformers 4.46) and `tokenizer=` → `processing_class=` (deprecated), the unused `notebook_login()` commented out, an environment cell.
- **Week 7** ([#8](https://github.com/xufana/dsba_nlp/pull/8)). `conll2003` is loaded as `eriktks/conll2003` with `trust_remote_code`; the NER label map comes from the dataset (the hand-written one swapped ORG and LOC); the QA metric decoded `label_ids` as token ids and the `Trainer` was not told which columns are labels (`label_names`); `answer_question` restricts the span to the context and enforces start ≤ end; XSum is loaded from its parquet mirror; `tokenizer=` → `processing_class=`. New in this repository, with the summarization part.
- **Week 8** ([#9](https://github.com/xufana/dsba_nlp/pull/9)). Environment cell only; no code changes were needed. New in this repository.
- **Week 9** ([#10](https://github.com/xufana/dsba_nlp/pull/10)). `langchain_qdrant.Qdrant` → `QdrantVectorStore` (the old class breaks with recent `qdrant-client`); the parent-document demo referenced an undefined variable; install cells consolidated; the Gemini example runs only with `GEMINI_API_KEY`. New in this repository, with `data/gonzo_dump.csv` and `data/golden_mock.xlsx`.
- **Week 10** ([#11](https://github.com/xufana/dsba_nlp/pull/11)). `num_workers=8` → 2 (Colab has 2 cores); the stray `!pip install` cell is removed. New in this repository.
- **Week 11** ([#12](https://github.com/xufana/dsba_nlp/pull/12)). `pip install vllm` without `%` was a syntax error and the vLLM part is marked Linux + CUDA only; `torch_dtype` → `dtype`; `display` imported; `feedbackQA` loaded with `trust_remote_code`. New in this repository.
- **Week 12** ([#13](https://github.com/xufana/dsba_nlp/pull/13)). The private `imdb_distilbert_checkpoint` is replaced by `lvwerra/distilbert-imdb`; `.cuda()` calls are device-aware and the GPU-only demonstration is skipped without CUDA; the ONNX static-quantization section (previously marked "does not work") is rewritten against the current `optimum` API, with an accuracy check and a dynamic-int8 comparison; the QLoRA cell referenced undefined names; `auto-gptq` → `gptqmodel`, `disable_exllama` → `use_exllama=False`. New in this repository.
- **Extra: agents and text diffusion** ([#14](https://github.com/xufana/dsba_nlp/pull/14)). Environment cell; `torch_dtype` → `dtype`. New in this repository.
- **All notebooks.** Colab `widgets` state is removed from the metadata (hundreds of KB per notebook; it also breaks GitHub's renderer) and the kernel spec is normalized to `python3`.

How this was checked: week 1 runs end to end with `jupyter nbconvert --execute` in the pinned environment; week 3 runs up to the RNN training, which was smoke-tested on CPU on a subset; the week 9 retrieval stack and the week 12 ONNX section were smoke-tested; the other notebooks were checked statically (pyflakes and an AST pass) because they need a GPU.
