## lede
Есть готовая языковая модель. Как научить её решать нашу задачу?

## s-intro
**При дообучении мы используем готовую модель и обучаем её на примерах своей задачи.** Например, хотим определять тему обращения, находить в нём организации или отвечать клиенту в заданном формате. Предобучение даёт исходные представления и умение работать с текстом; теперь нужно приспособить их к нужному выходу.

## intro-route
- **Определить задачу и критерий качества.** Что подаём на вход, какой выход ожидаем и как поймём, что модель справилась?
- **Подготовить примеры и отдельную проверочную выборку.** Сначала проверяем на ней исходную модель, затем сравниваем с результатом дообучения.
- **Выбрать, что обучать и по какому сигналу.** Можно обновлять всю модель или небольшую часть параметров. Для обучения могут быть доступны правильные метки, образцовые ответы, сравнения ответов или программа, проверяющая результат.

## intro
**Какие параметры менять?** Для классификации можно добавить линейную голову и обучить только её на замороженных представлениях — это linear probing. Можно дообучать и саму модель. Методы PEFT уменьшают число обучаемых параметров; в LoRA обучаются небольшие добавки к матрицам модели. С этого начнём лекцию.

**На чём учить отвечать?** Если есть образцовые ответы, учим модель предсказывать их токены — это SFT. Если есть пары «этот ответ лучше того», можно использовать DPO. Если ответы оценивает модель награды или программа, разберём обучение по награде с PPO и GRPO.

Это два отдельных выбора: например, SFT можно проводить с LoRA. Сначала определяем, какое поведение нужно и какие данные для него есть, затем выбираем способ обновления параметров.

## s-policy
**Источник награды и алгоритм обновления — два выбора.** Человек или программа задают критерий; PPO или GRPO обновляют модель по полученной награде.

## policy-detail
Для обучения нужно подготовить:
- **SFT:** запрос и пример желаемого ответа.
- **DPO:** запрос и пару ответов с отмеченным предпочтением.
- **PPO / GRPO:** запросы, ответы самой модели и способ выдавать награду.

В RLHF модель награды учится на человеческих предпочтениях. В RLVR результат оценивает программа: например, проверяет ответ задачи или запускает тесты кода. PPO и GRPO задают, как обновлять языковую модель по этим оценкам.

## grpo-kl
Даже когда награды не различают ответы, штраф KL за отличие от исходной модели может продолжать менять параметры. Отсутствие сигнала от награды само по себе не означает, что всё обучение остановилось.

## q-ppo-trained · pick
Модель награды уже обучена. Запускаем PPO для языковой модели. Какие компоненты теперь обучаются?
- [x] языковая модель (policy)
- [ ] исходная модель (reference)
- [ ] модель награды
- [x] оценщик ожидаемой награды (critic)
> Policy учится выбирать ответы, critic — оценивать ожидаемый результат. Reference и модель награды заморожены.

## q-ppo-clip · pick
Преимущество токена положительно. Отношение его текущей вероятности к старой уже выше верхнего порога PPO. Будет ли ограниченное слагаемое цели поощрять дальнейший рост этой вероятности?
- [x] нет: это слагаемое больше не растёт
- [ ] да: чем выше вероятность, тем больше это слагаемое
- [ ] только если обновить исходную модель (reference)
> Clipping ограничивает выгоду движения, которое уже ушло слишком далеко в нужную сторону. Это свойство слагаемого цели; другие слагаемые рассматриваем отдельно.

## q-grpo-flat · pick
Все ответы на один запрос получили одинаковую награду. Может ли GRPO по этим наградам выделить ответы, вероятность которых нужно повысить?
- [x] нет: ни один ответ не лучше среднего по группе
- [ ] да: нужно повысить вероятность всех ответов
- [ ] да: нужно понизить вероятность всех ответов
> Из каждой награды вычитается то же самое среднее. Числитель равен нулю. В вычислении стандартного отклонения используется малое ε для этого случая.

## q-methods · sort
Какой обучающий сигнал соответствует методу?
bins: готовый ответ · пара предпочтений · награда за собственный ответ
- SFT → готовый ответ
- DPO на фиксированном наборе → пара предпочтений
- PPO → награда за собственный ответ
- GRPO → награда за собственный ответ
> При SFT целевые токены даны. DPO сравнивает два готовых ответа. PPO и GRPO используют ответы, порождённые policy во время обучения.

## q-design · write
Есть готовая языковая модель, диалоги поддержки и несколько тысяч пар предпочтений. Нужно научить отвечать в заданном формате на одной GPU. Предложите план.
- задача и формат ответа
- разделение диалогов на обучение и проверку без утечки клиентов
- SFT на ответах и маска labels
- выбор обучаемых параметров: LoRA или полное дообучение
- DPO на предпочтениях, reference и независимая оценка
- метрики качества, соблюдение формата и возможные отказы
> Начните с проверки исходной модели. SFT задаёт примеры ответа, LoRA уменьшает число обучаемых параметров. DPO использует предпочтения. Эффект каждого этапа проверяем отдельно на отложенных запросах.

## s-ppo
**PPO повышает вероятность действий, оказавшихся лучше ожиданий.** Обновление учитывает, насколько вероятности уже изменились на текущей порции ответов.

## ppo-detail
PPO запоминает вероятности модели, породившей текущую порцию ответов: `π_old`. При нескольких обновлениях на этой порции отношение `π_θ / π_old` учитывает изменение policy. Clipping ограничивает увеличение целевого слагаемого, когда движение в выгодную сторону уже превысило порог. Если вероятность хорошего ответа упала, ограничение не мешает вернуть её вверх.

Reference `π_ref` задаёт штраф KL за отличие от исходной модели. Critic оценивает ценность префикса. В одношаговой задаче практики advantage — результат минус baseline; в последовательности токенов используют оценки будущих наград.

## ppo-mechanism
Модель генерирует ответы, а модель награды оценивает результат. Critic оценивает ожидаемую будущую награду по каждому префиксу. Из этих оценок получают **преимущество (advantage)** для токенов: положительное поощряет выбранный токен, отрицательное — уменьшает его вероятность.

На одной порции ответов делаем несколько обновлений. Для каждого выбранного токена сравниваем текущую вероятность с вероятностью **в момент генерации**. Отношение вероятностей и **ограничение (clipping)** входят в цель PPO. Это помогает сдерживать чрезмерное изменение на одной порции данных. Исходная модель reference отдельно задаёт штраф KL; сохранённые вероятности генерации обновляются при сборе новой порции ответов.
